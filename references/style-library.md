# 风格库与选型

来源：2026-10-12 整理自一条公开分享的"28 种纯代码视频风格提示词"合集视频。逐帧读了视频里 28 条提示词与标签，下面是我们自己的归纳，不转载原文。原视频声明"含 AI 生成内容"，每种风格只是一段 8 秒的纯代码演示，不是讲解视频。拿来当画风素材库，不能当成片模板。

## 一条风格提示词由什么组成

原作每条提示词的写法几乎相同，可以直接当作我们设计一段画面的检查表：

1. **时长和风格名**：一段 N 秒、某某风格。
2. **底与配色**：底色、材质或纹理，限定在 2—4 种颜色。
3. **3—4 个按时间排好的动作**：每个动作有明确的主体和动词，比如"弹入""依次落下""沿虚线飞行""数字滚动"。
4. **收尾定格**：最后出现一个结论物，比如徽章、价格、标题、印章、"STAGE CLEAR"。
5. **技术标签**：三个关键词，说明靠什么实现，比如"弹性缓动""距离场""透视网格"。

对应到我们的稿件：第 3 项就是 `[[锚点]]` 触发的动作序列，第 4 项就是每段的"小结物"。设计分镜时，每段都要能写成这五项。写不出第 3 项，说明这段还没想好画面。

## 28 种风格

列说明：
- **实现**：在 Remotion 里怎么做。DOM/SVG 最稳；Canvas 2D 适合大量粒子和逐像素效果；WebGL 用 `@remotion/three` 或自写着色器，首次使用要先做 3 秒样片，确认渲染速度。
- **适合**：对我们账号内容（iOS 开发教程、AI 知识、测评、vlog）的适配度。

## 我们已有的组件对应哪些风格

首个样片（一条 iOS 适配与提交教程）主要是 1 扁平 MG＋5 产品界面演示，局部用了 4 数据新闻（数字滚动）和 8 白板（框线一笔画出）。现有组件：

| 组件 | 作用 | 可复用到 |
|---|---|---|
| `FocusRing` | 焦点框依次移到讲到的元素 | 1、5、19 |
| `Flyer` | 小标签沿弧线飞行，表现数据流向 | 1、3、19 |
| `Typed` | 逐字打出 | 5、9、28 |
| `ReadAlong` | 跟读变色 | 9 |
| `CountUp` | 数字滚动 | 4、6、19 |
| `DrawBox` | 框线一笔画出 | 8、24、27 |
| 圆形遮罩转场 | 从内容原点展开新场景 | 5（深色模式展开）、通用转场 |

按需补的组件（用到时再做，先做 3 秒样片确认效果和渲染速度）：
- **描线 `DrawPath`**：任意 SVG 路径一笔画出（8、24、27）。
- **形变 `Morph`**：路径间插值（2）。
- **等轴舞台 `IsoStage`**：等轴投影容器（3）。
- **图表**：折线→柱状→环形转换（4）。
- **虚拟光标 `Cursor`**：移动、点击涟漪（5）。
- **粒子文字 `ParticleText`**：Canvas 实现（20）。
- **故障转场 `GlitchCut`**：不超过 1 秒（18）。
- **蓝图底 `BlueprintGrid`**、**齿轮 `Gear`**（27）。
- **脉冲 `Pulse`**：亮头渐隐尾、单向、分车道的数据流（30，也可升级 1、3、19 里的 `Flyer` 用法）。
- **定位仪表 `ScaleBar`、`TimeMeter`、`ElapsedClock`**：放在 Stage 固定层，只变数字（30）。
- **推进换场 `ZoomThrough`**：推进到上一场景里已画出的小部件，推完即静止（30）。
- **路线回顾 `RouteRecap`**：全片站点连线，主角沿线快速走一遍（30）。

## 选型方法

1. **先定内容类型和情绪**，再挑风格：
   - 教程讲原理：27 工程蓝图或 8 白板为主，1 扁平 MG 承接流程。
   - 写代码、讲 API、演示 Demo 效果：29 开发实录为主，章节页可配 9 动态排版。
   - 新特性、发布会：15 弥散玻璃做底，5 界面演示讲功能，9 动态排版做标题。
   - AI 知识、Agent：3 等轴讲系统组成，19 HUD 表现"在工作"，28 字符渲染讲命令行，20 粒子成形用于片头关键词。讲"某样东西怎么走完一遍"（一次请求、一个 token、一次工具调用）时，用 30 旅程式讲解组织全片，主风格可以仍是 3 等轴或 1 扁平。
   - 测评：4 数据新闻为主，5 界面演示做前后对比。
   - 旅行或生活 vlog：24 一笔线条、23 剪纸、13 低多边形做开场，正文用真实画面。
2. **一条片子只用一种主风格**，承担 70% 以上的画面；再选一到两种点缀风格，只用在片头、转场或某个特定段落（比如讲 bug 的那一秒用 18 故障）。三种以上会显得乱。
3. **固定层不随风格变**：标签、标题位置、字幕、页脚、品牌头像保持系列一致，换的是底、对象和动作。
4. **风格服务信息**：只有氛围、不承载信息的风格（12、14、16、17）只能用在片头、转场，每次不超过几秒。
5. **真实素材优先**：真实截图、官方画面、设备母版不能被风格化重绘；风格只作用于周围的示意层。
6. **成本先试**：WebGL、粒子、模糊类风格先渲染 3 秒，量一下每秒能渲几帧，再决定是否整段使用。

## 三个参考原则（不是硬性要求）

来自用户看到的其他视频介绍，作为设计时的自检，不要求每条都满足：

1. **每句话都有一个看得见的画面**：和我们的 `[[锚点]]` 做法一致。检查方法：逐句看分镜表，说不出"这句画面上变了什么"的句子，要么补画面，要么删掉这句。
2. **每个动作都踩在节拍上**：现在动作踩的是旁白的词。可以再进一步，让较大的动作（换场、卡片砸入、数字落定）对齐配乐的拍点：124 BPM 时一拍约 14.5 帧，把锚点附近 ±3 帧内的动作吸附到最近的拍上，不影响和词的同步感。要先确认配乐 BPM 和起拍时间，现成曲库的音乐要先测拍。
3. **整条片子用一个线索穿到底**：选一个贯穿对象或隐喻，从开场带到结尾。比如一条三步教程可以用"那条三步路线"或"同一台设备"；讲 AI 可以用"一条消息的旅程"。每段换场时，线索对象留在画面里，或者从上一段带过来，结尾回到它。讲机制、流程类内容时，这一条从参考升为默认做法，按 #30 旅程式讲解做：主角带编号、独占强调色，每段都能说出"它现在在哪"。
