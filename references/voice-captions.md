# 旁白与字幕同步

## 数据来源

优先保存 TTS 音频、原生词边界与生成文稿，并归一化核对词边界文本是否完整对应文稿。原生时间是生成服务的时间信息，仍需抽查首句、末句、技术词和数字。不要把有时间信息等同于已经人工听过。

原生时间不可用时，对最终旁白做 ASR，人工校正文稿，再用强制对齐工具校时。可参考 [WhisperX](https://github.com/m-bain/whisperX)；要先确认模型、语言、依赖、下载大小与实际硬件条件。直接使用语句级 ASR 的时间不能宣称逐字准确。

可选中文声音入口：[edge-tts](https://github.com/rany2/edge-tts) 的在线神经语音；[Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS) 的本地或托管方案；用户已配置的其他 TTS。先试音验证可用性，记录提供方与声线，不模仿参考博主个人声纹。

## 对齐流程

1. 一段完整讲解生成一次声音，不为每条字幕重新生成声音。
2. 保存返回的词事件；按语义归并成短句，不用字数除以总时长估计。
3. 音频加入开头停顿时，字幕起止都加相同偏移；剪掉静音或更改语速同理。
4. 重叠词边界归并后，字幕尾点最多截到下一条起点。短间隙可保持前条字幕，防止闪烁。
5. Caption JSON 使用媒体局部毫秒：`text, startMs, endMs, timestampMs, confidence`。无可靠置信度或逐词中心时间时填 null。
6. 全局 SRT 在输出时加场景开始时间一次。旁白与字幕位于同一场景，避免音频和画面各自偏移。
7. 保存对齐所用最终音频的 SHA-256。摘要只防止换音频后沿用旧时间，不证明准确同步。

## 阅读与声音

字幕优先一行，必要时两行；按真实字形宽度检查，英文 API 不能按汉字字数机械换行。移动端安全区预留平台控件空间，字号按画幅和实测预览调整。不要在没有词级时间时做卡拉 OK 式逐字高亮。

参考视频句间停顿多在 0.2 秒以内、换章 0.4—0.8 秒，语速约 320—360 汉字/分钟。edge-tts 在标点处会插入较长停顿，可整段合成后按词边界压短（句末约 0.20 秒、句内约 0.09 秒），并同步平移词时间；压缩后用 ASR 回听确认没有吞字。字幕一帧硬切、首尾相接；稿件可用 `|` 指定断条。详见 [音画联动与节奏](motion-sync.md)。声音测量检查峰值、响度和意外静音；读法、情绪、机械感需要听音复审。字幕准确与旁白自然是两项不同检查。

## 克隆本人声音（2026-10-10 验证可用）

- 模型：mlx-audio 0.5.8 的 Qwen3-TTS（`mlx-community/Qwen3-TTS-12Hz-1.7B-Base-8bit`），本机生成速度约为实时的 1.3 倍。同一参考录音下，它的中英混读明显好于 F5-TTS 和 VoxCPM2。
- 参考录音：10—20 秒、背景干净、含若干英文词的本人讲话，ref_text 必须与录音逐字一致。参考里英文越多，中英衔接越自然。
- 参数：
  - `lang_code="auto"`。强制 chinese 会让英文前后出现停顿，听起来脱节。
  - `temperature=0.7`。
  - 稿件中英之间不加空格，驼峰词不拆开。
- 对齐：克隆模型没有词边界。对每段最终音频做 Whisper 逐字识别，再与稿件逐字比对（difflib），没对上的字插值。
  - 不要把稿件原文作为 Whisper 提示词，实测会让对齐率从 95% 以上掉到 27%。
  - 对齐率低于 90% 要抽查。
- 节奏：先按静音压短长停顿，再用 atempo 小幅加速（保持音高）到目标语速，最后对齐。对齐必须基于最终音频。
- 同步复核：
  - 用能量起声检测，比较字幕起点与真实起声。
  - 不要用 Whisper 对整条长音轨的识别结果当依据：它有约 −160 毫秒的系统偏移。
- 只克隆用户本人或已获授权的声音，发布时按平台规则标注 AI 合成。
- 读音替换：克隆模型把个别英文 API 读坏时（如 `UIScreen.main` 被读成"UI 是 main"），只在送给 TTS 的文字里替换写法（如"UI Screen点main"），字幕和画面仍显示原文。同一写法每次采样也可能不同，可以换几个随机种子合成，用 Whisper 检查该词，挑读对的一版。
- 反复出现的英文产品名要保持声调一致：克隆模型在句中常给它随机加上升调、降调或曲折调，听起来"前后发音不一样"。换随机种子通常没用。可以在送给 TTS 的文字里改成同音的中文平调写法，并注意连读：Duo 写成"多欧"会断成"度—欧"，"多喔"又会并成单个"多"，用户最终选"嘟喔"。更好的办法是少读这个词：能用通用说法（如"折叠屏"）就换掉。这类听感差异，最后要做一段试听对比请用户选，不要只凭测量连续盲改。单位缩写（如 MB）字母分开写，避免读成"兆比"，再用元音段 F0 的首、中、尾差值（半音）挑出平调的一版。频谱距离受相邻字影响大，不适合判断这个问题。
