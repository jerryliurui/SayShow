# 内容动画的制作方法

文案不是长文缩短后逐行显示。先明确听众这一段要理解的因果，再选择画面。

| 内容 | 可用画面与动作 | 避免 |
| --- | --- | --- |
| 扫描与人工复查 | 问题进入清单，人工确认补齐 | 假造实际扫描结果 |
| 窗口尺寸变化 | 普通内容区域连续缩放并换行 | 拉伸真实机身和截图 |
| 新旧 SDK 差异 | 官方原图依旁白切换，保留阅读时间 | 重绘官方 UI |
| 状态保持 | 同数据、同文章真实截图前后展示 | 用生图冒充运行证据 |
| 多种工具 | 依讲解逐项出现，标明各自目的 | 把所有测试写成已经完成 |
| 提交步骤 | 流程连接、当前节点强调 | 每句话都加弹跳与音效 |

动作按旁白的词触发，不只按句触发；具体手法、待机动效、转场和节奏数字见 [音画联动与节奏](motion-sync.md)。新场景先交代主问题，再出现细节与小结。关键结论出现后，主体可以停住供阅读，但背景、镜头仍保持轻微运动，不出现长时间完全静止的画面。独立场景是独立源文件和时间线节点，便于逐段修改。开场与场景编排按每篇内容设计，不把某一篇的处理固定成模板。

内容动画须给每个对象写清“出现／持续／变化／让出空间”的路径。讲聚合就让元素归组，讲扫描就让文件与放大镜接到待复查清单，讲尺寸变化就真正改变可用宽度并让内容重排。同一对象在前后句中继续承担角色，不能只换配色与大标题。画面丰富度来自解释关系与动作，不是机械规定每屏至少六个装饰。

写口语稿时，用具体情况开头，接上实际做法与结果。减少“先核对、再验证、最后总结”的连续模板句，减少抽象金句和报告式小结。先把稿件读顺，再按最终旁白的语义起点安排视觉动作。需要提速时同时精简重复句、调整语速和章间空白；保留数字、命令与来源条件的阅读时间。

文字、代码、字幕用真实字体排版；字体文件、字重、换行、溢出和小尺寸预览一起检查。画风一致靠配色、字体与空间，而非每段堆同一个角色。品牌元素按用户项目约定使用。

画幅单独决定：参考账号是竖版封面＋横版 1920×1080 正文。画幅和帧率按项目约定，不能写成平台强制规格。教程讲解视频与 App Store App Preview 是不同交付物。

真实截图与概念动画分别标注；保留原始来源文件。视频整理必须保留完整视频标题与来源，发布文案提供可查链接。规格和日期具有时效性，制作当日核对官方材料。

音乐用于托住节奏，不代替旁白表达。优先用户可用且来源明确的素材，或原创生成，并在发布文案写明来源；风格按项目约定。说话时压低、停顿时回升，客观测量通过后仍需人工听感检查。

Review 记录：内容覆盖与删减理由、事实与版本、截图来源、字幕同步方法、动画与文字抽查、音频测量、未验证事项、最终文件规格。只记录实际做过的检查。
