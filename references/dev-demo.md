## 哪些必须真实，哪些可以排版

| 内容 | 默认做法 | 说明 |
|---|---|---|
| 运行效果 | **必须真实**：模拟器录屏或真机录屏 | 不能用动画假装运行结果。设备外形以真实型号为准：新机型（如折叠屏）用对应模拟器或真机的真实边框，不用泛化外框代替 |
| 写代码的过程 | 默认用 `CodeEditor` 排版：代码就是实际编译运行的那份，逐字打出、高亮行、推近 | 画面清晰（1080p 文字锐利）、和旁白逐词同步、没有打错字和等待。Note 写明"代码排版演示，运行效果为模拟器实录" |
| IDE 本身的操作（快捷键、补全、预览、调试器、Xcode 新功能） | **必须真实录屏** | 讲的就是 IDE 行为，排版会失真 |
| AI 编程工具（Claude Code、Codex、Xcode 编程助手）的交互 | 真实录屏为主；终端命令可用 `Typed` 排版补充 | 对话和生成结果必须是真实一次运行的记录，不能编造输出 |

## 素材怎么拿到

1. **模拟器录屏**：可以由 Claude 完成。
   - 用 xcodebuild 构建，装到模拟器，按演示步骤点按（iOS 模拟器工具）。
   - 用 `xcrun simctl io booted recordVideo --codec=h264 文件.mp4` 录制，Ctrl-C 结束。
   - 关掉通知、统一时间（`xcrun simctl status_bar booted override --time 9:41`），用虚构的演示数据。
2. **Xcode 等 IDE 录屏**：两种方式。
   - 用户自己录（推荐，最自然）。准备：深色主题、字号 16 以上、只开相关文件、隐藏无关面板、关掉通知；QuickTime 或 `screencapture -v` 录到 1440p 以上；可选 KeyCastr 这类按键显示工具，或另外记下每次按键的时间。
   - Claude 用电脑操作（computer use）驱动 Xcode，同时 `screencapture -v -R x,y,w,h` 录区域。适合短而确定的操作，比如演示几个快捷键。录制时记下每一步的时间，作为键帽叠加的时间点。自动补全和索引状态不可控，长段写代码不适合这样录。
3. **真机录屏**：用户在手机上录屏后传过来，或用 QuickTime 连接录制；裁掉状态栏里的个人信息。

所有录屏放到 `remotion/public/video/`，原始素材另存在该篇 `素材/` 下，不覆盖。

## 后期组件（`src/kit/dev.tsx`）

- `CodeEditor`：Xcode 深色主题、行号、Swift 着色。
  - `inserts` 让某一段代码在指定帧内逐字打出，新行逐行长出来，行号随之顺延，带光标。
  - `focus` 给某几行加高亮带。
- `ScreenClip`：嵌入真实录屏，可变速（无聊的等待用 `rate` 加速）；`zooms` 按锚点推近到录屏某个区域，推近后不露边。
- `KeyCaps`：键帽依次按下，下方紫色标签写作用。位置放在受影响的界面区域旁边。
- `PhoneFrame`：通用 iPhone 外框（灵动岛），装模拟器录屏。外形不同的机型（如折叠屏）不用它，改用真实边框。
- `ChapterTag`：编号＋中文＋英文的描边章节标签，沿用旧视频样式。
- 通用组件照常可用：`FocusRing` 框住录屏里的按钮，`Flyer` 表现数据流，`TitleDrop` 和提纲卡做章节页。

## 节奏

- 有旁白（变体 B）：动作照常由旁白的 `[[词]]` 触发，代码打字速度服从旁白。一行代码对应一句话，不要整段一起冒出来。
- 只有配乐（变体 A、C）：键帽、推近、换步骤对齐配乐拍点。配乐用 `music.py`，拍点按 BPM 算；现成曲目先测拍。
- 录屏里的等待（编译、加载）加速或剪掉；操作发生的那一秒要清楚可见，必要时推近。
- 开头 1.5 秒柔和进入，结尾沿用通用片尾或快捷键汇总卡，见项目 AGENTS.md。

## 隐私与真实性

- 录屏前关掉通知，检查工程名、路径、账号、API Key、证书、真实用户数据；用虚构数据。
- 不把排版代码说成"现场写的"，也不把模拟器结果说成真机实测。没测过的姿态、设备和系统版本，在 Note 或旁白里说明。
